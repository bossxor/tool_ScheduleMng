## 2. 기능 — 아직 없음

### 습관
- 시작일 선택(지금은 오늘 고정, 과거 날짜 선택 필요)
- 습관 그림 선택(45개)과 스티커 모음 화면, 마일스톤 스티커(3·7·30·100일)
- 추천 습관 6개 중 나머지 3개(일기 쓰기, 일찍 자기, 운동 주 3일)
- 습관 상세의 메모·알림 목록 표시
- 주간 띠에서 일부 달성한 날의 진행 링 표시
- 보관한 습관 읽기 전용 상세 정리

### 알림
- 수량·시간형 알림의 ‘기록하기’ 액션(해당 날짜 입력 화면 열기)
- 지난 알림 누락 표시
- 종일 작업 알림 시각 설정, 작업 알림(완료·10분 미루기)
- 정확한 알람이 막힌 경우의 안내

### 타이머
- 타이머 화면이 켜져 있는 동안 화면 꺼짐 방지
- 다른 습관 타이머를 시작할 때 저장/버리기 선택 안내
- 목표 도달 시 알림(M2에서 재검토)

### 할 일·일정 (설계 M1-C, M1-D)
- 목록(받은함 외 사용자 목록), 태그, 체크리스트, 수동 순서(M3)
- 날짜·시간 지정, 반복(일·주·월·년, 요일, 종료일), 회차 완료·되돌리기
- 반복 일정의 캘린더 표시(미래 회차 계산)
- 검색(제목·메모)

### 공통
- 테마 선택(시스템/밝게/어둡게), 달성 효과 진동 설정
- 달성 시 스티커 전환 효과, 전부 달성 문구(하루 한 번)
- 오픈소스 라이선스 화면(글자체·그림 출처)
- 데이터 파일 읽기 실패 시 복구 화면(백업 선택, 스냅샷 되돌리기)

## 5. 출시 준비

- 코드 축소(R8) 적용과 APK 크기 점검(현재 약 23MB)
- 릴리스 절차 확정: `Harugyeol-vX.Y.Z.apk` 이름, 릴리스 노트, 사전 릴리스로 먼저 시험
- 첫 공개 릴리스(0.1.0)와 자동 업데이트 종단 간 시험(이전 버전 설치 → 새 릴리스 → 업데이트 → 데이터 유지)
- 서명 키 백업을 다른 위치에 한 부 더 보관(사용자 작업)
- 설치 안내 문서와 스크린샷

## 6. 기술 부채·결정 필요

- 데이터 파일은 변경마다 전체를 다시 쓴다. 규모가 커지면 연도별 분리를 검토한다.
- `schemaVersion` 1에서 필드를 바꾸면 이전 파일을 읽지 못할 수 있다. 출시 전까지는 허용, 출시 후에는 변환 함수가 필요하다.
- 습관 추가 시 ‘추가 후 편집’ 두 번의 변경으로 알림 시각을 붙인다. 한 번의 연산으로 합치는 정리가 필요하다.
- 시간 습관 카드는 분 단위로 내림해 표시한다(초 단위 표시 여부 결정).
- 하단 메뉴 아이콘이 글자뿐이다. 윤곽선 아이콘 디자인 결정이 필요하다.
- 패키지 ID `com.bossxor.harugyeol`과 서명 키는 확정이므로 변경하지 않는다.

## 7. 권장 순서

1. `wip/tasks-backup-update`를 리베이스하고 실기기에서 확인한 뒤 테스트를 보강해 `main`에 합친다(하단 메뉴·할 일·캘린더·백업).
2. 앱 업데이트를 실제 릴리스로 종단 간 시험한다.
3. 반복 일정과 작업 알림(M1-D).
4. 습관 시작일 선택, 알림 ‘기록하기’ 액션, 타이머 보완.
5. 디자인 자원(그림·아이콘), 스티커 모음, 테마·접근성·어두운 모드 점검.
6. 0.1.0 릴리스 준비와 배포.
