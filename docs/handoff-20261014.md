# 원래 개발 PC에서 최종 빌드

사용자 요청에 따라 서명·최종 APK 빌드·배포는 원래 개발 PC에서 진행한다.
수정 브랜치: `codex/fix-five-verified-issues`. [PR #1](https://github.com/bossxor/tool_ScheduleMng/pull/1).
main에는 아직 병합하지 않았다. 원래 PC에 미커밋 변경이 있으면 먼저 보존한다.

```powershell
git fetch origin
git switch codex/fix-five-verified-issues
git pull --ff-only origin codex/fix-five-verified-issues
```

## 완료한 작업

- 알림·저장·날짜·타이머 결함 5개 수정. [상세 보고](five-fixes-20261013.md).
- 단위 테스트 95개, R8 릴리스 빌드, lint 통과(오류 0·경고 21).
- Android 13 에뮬레이터와 S26 Ultra / Android 17 런타임 회귀 검증 통과.
- 검증 앱 제거 완료. 기존 개인 앱은 v0.1.1 / versionCode 3 그대로다.
- 이 PC의 릴리스 APK는 서명 설정 없이 만든 검증용이다. 공개·설치하지 않았다.

## 원래 PC에서 할 작업

1. 기존 서명 키를 사용한다. 기본 설정 경로는 `%USERPROFILE%/harugyeol-keys/keystore.properties`다. 키와 비밀번호는 Git에 넣지 않는다. 다른 경로는 Gradle의 `-Pharugyeol.keystoreProperties=...`로 지정할 수 있다.
2. 배포 전 `app/build.gradle.kts`의 versionCode를 3보다 높이고 versionName을 다음 릴리스 번호로 변경한다. 권장: versionCode 4, versionName 0.1.2.
3. JDK 17·Android SDK 37 환경에서 다음 명령을 실행한다.

```powershell
.\gradlew.bat testDebugUnitTest assembleRelease lintRelease
```

4. 산출물 `app/build/outputs/apk/release/app-release.apk`의 서명 인증서가 기존 v0.1.1과 같은지 `apksigner verify --verbose --print-certs`로 확인한다. unsigned APK를 배포하지 않는다.
5. 기존 앱을 삭제하지 않고 서명 APK를 덮어 설치한다. 기록·타이머 유지와 수정 동작을 확인한다. 실제 Doze 지연·물리적 재부팅·전체 UI 조작은 아직 미검증이다.
6. 버전 변경과 릴리스 노트를 커밋하고 PR 병합·태그·GitHub Release 및 APK 업로드를 마무리한다.

현재 저장소의 앱 버전은 아직 0.1.1이다. 이번 수정은 공개 v0.1.1 APK에 포함되지 않았다.
